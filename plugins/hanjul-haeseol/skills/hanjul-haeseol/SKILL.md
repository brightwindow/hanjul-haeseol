# 한 줄 해설 (고졸판)

강의 슬라이드를 **원문 한 줄 : 해설 한 덩어리**로 짝지어 HTML 한 벌을 만든다.
읽는 사람은 **고등학교 수학(미분이 기울기라는 것)까지만 알고, 그 과목 용어는 하나도 모르는 사람**이다.

## 가장 중요한 규칙

**손글씨가 인쇄된 글자보다 값지다.** 교수가 펜으로 적은 것은 "이건 알고 가라"는 신호다.
텍스트 추출로는 손글씨가 전부 깨져 나오므로 **반드시 모든 쪽을 이미지로 떠서 눈으로 본다.**
이 단계를 건너뛰면 자료의 절반을 버리는 것이다.

**없는 것을 지어내지 않는다.** 손글씨가 정말 안 읽히면 `[필기] (판독 불가)` 로 정직하게 둔다.
슬라이드에 없는 공식이나 수치를 채워 넣지 않는다.

## 작업 순서

### 1단계 — 쪽을 뜯어낸다

스크립트는 **이 SKILL.md 와 같은 폴더의 `scripts/`** 안에 있다.
플러그인으로 깔았든 `~/.claude/skills/` 에 폴더째 복사했든 상대 위치는 같다.
절대 경로가 필요하면 `SKILL.md` 가 있는 폴더를 기준으로 잡는다.

```bash
python "<스킬폴더>/scripts/pdf_pages.py" "<입력.pdf>" "<작업폴더>"
```

`pNN.png`(140 dpi)와 `pNN.txt`가 쪽마다 나온다. **텍스트가 유난히 짧은 쪽은 손글씨 쪽이라고 표시해 준다.**

- **환경 주의** — `pdftoppm` 이 없는 환경이 흔하다. 이 스크립트는 PyMuPDF(`fitz`)만 쓴다.
  기본 `python` 에 `fitz` 가 없으면 Anaconda 쪽을 부른다. 예: `C:/Users/<사용자>/anaconda3/python`
- Read 도구로 PDF 를 직접 여는 것은 쪽 수가 많으면 실패한다. 항상 이 스크립트를 먼저 돌린다.

### 2단계 — 모든 쪽을 눈으로 본다

`pNN.png` 를 **한 장도 빠뜨리지 말고** Read 도구로 연다. `pNN.txt` 는 참고용이다.
쪽마다 네 가지를 따로 적어 둔다.

| 무엇 | 어떻게 다룰지 |
|---|---|
| 인쇄된 본문 | 원문 그대로. 영어면 영어 그대로 둔다 |
| 손글씨 필기 | `[필기] ...` 로 감싼다. 읽히는 대로 최대한 복원 |
| 그래프·그림 | 그림 설명 상자. "이 그림은 ~" 으로 시작 |
| 붉은 동그라미·별표·밑줄 | 시험 포인트 상자. **강조가 실제로 있던 자리만** |

전부 손글씨인 쪽(Overview, 요약 쪽)이 가장 값지다. 대개 그 과목 한 장 요약이다.

### 3단계 — 해설을 쓴다

**쓰기 전에 두 문서를 반드시 읽는다.**

- [references/example.md](references/example.md) — 실제로 만든 결과에서 뽑은 세 가지 본보기.
  인쇄 본문 쪽, 전부 손글씨인 쪽, 붉은 강조가 있는 쪽이 각각 어떤 밀도로 나오는지 보여 준다.
  **밀도와 어조를 여기에 맞춘다.**
- [references/writing-rules.md](references/writing-rules.md) — 용어 푸는 법, 수학 기호 번역표, 검증된 비유.

- 전문 용어는 **그 쪽에서 처음 나올 때마다** 일상어로 푼다. 앞 쪽에서 설명했어도 다시 푼다.
- 식은 **① 기호가 뭔지 → ② 식이 하는 말 한 문장 → ③ 왜 이 모양인지** 순서로.
- 비유를 쓰되 **반드시 정확한 서술로 되돌아온다.**
- `~다` 체 평서문. 짧은 문장. 해설 한 덩어리는 2~6 문장.

### 4단계 — 조각 파일로 적는다

쪽마다 조각 하나씩 `fragments.json` 에 쌓는다.

```json
[
  {"page": 1, "title": "표지", "html": "<div class=\"row\">…</div>"},
  {"page": 2, "title": "Overview — 전체 지도", "html": "…"}
]
```

`html` 칸에 쓸 수 있는 마크업은 여섯 가지뿐이다.

```html
<div class="row"><div class="orig">원문</div><div class="exp">해설</div></div>
<span class="hand">[필기] ...</span>        <!-- 원문 칸 안에서 손글씨 -->
<div class="fig">이 그림은 ...</div>         <!-- 그래프·그림 설명 -->
<div class="exam">★ 시험 포인트 — ...</div>  <!-- 붉은 강조가 있던 곳만 -->
<div class="key">정리 ...</div>              <!-- 배경·요약 -->
<h3>소제목</h3>                              <!-- 쪽 안에서 갈래를 나눌 때 -->
```

- 수식은 MathJax 없이 **유니코드 + `<sub>` `<sup>`** 로 쓴다. 예: `n₀`, `δn`, `τ<sub>n0</sub>`, `e<sup>−t/τ</sup>`
- `h1` · `h2` · `section` 은 쓰지 않는다. 조립할 때 자동으로 붙는다.
- JSON 을 셸 heredoc 으로 쓰지 않는다. 한글과 백슬래시에서 깨진다. **Write 도구로 파일을 만든다.**

### 5단계 — 조립한다

```bash
python "<스킬폴더>/scripts/build_html.py" \
       "<fragments.json>" "<원본이름>_한줄해설_고졸판.html" "<문서 제목>"
```

빠진 쪽, 겹친 쪽, 태그 짝이 안 맞는 곳을 **자동으로 잡아 준다.** 경고가 나오면 고치고 다시 돌린다.

**출력 파일은 원본 PDF 옆에** 둔다. 이름은 `<원본이름>_한줄해설_고졸판.html`.

## 분량 감각

한 쪽에 해설 줄 5~10 개가 보통이다. 전부 손글씨인 요약 쪽은 15 줄까지 간다.
슬라이드 18 쪽이면 해설 줄 120 개 안팎, 완성본 80 KB 정도가 나온다.

원문에 있는 줄을 **줄이지 않는다.** 사소해 보이는 조건이 뒤에서 식을 지우는 근거가 되므로 전부 살린다.

## 하지 않는 것

- 원문 칸을 의역하거나 요약하지 않는다. 그대로 옮긴다.
- 시험 포인트를 임의로 만들지 않는다. **붉은 강조가 실제로 있던 자리만** 표시한다.
- 손글씨를 "고쳐" 적지 않는다. 오기가 있어 보이면 그대로 옮기고 해설 칸에서 짚는다.
- 슬라이드에 없는 예제나 문제를 만들어 넣지 않는다.
